# 015 — Dados sintéticos para volume HTTP

- Escopo: uma instrução SQL parametrizada para preparar banco efêmero migrado antes dos testes de volume autorizados pelo usuário.
- Responsável: agente replication; coordenador executa/mede API e valida a carga final.
- Branch/worktree: `feature/015-dados-volume`, `/private/tmp/naporta-015`, criada de `origin/develop` atualizado.
- Arquivos próprios: `database/seeds/volume.sql`, este registro. Sem alterações em migrations ou seeds de demonstração.
- Dependências/uso: Node `pg.query(sql, [orderCount])`, dentro de transação do chamador em banco efêmero explicitamente autorizado. Parâmetro inteiro entre 1 e 1.000.000; entrada inválida reprova a operação. Não executar no ambiente persistente do usuário.
- Contrato: UUIDs públicos aleatórios; números `SYN-VOLUME-000000001`; snapshots com até 10.000 documentos compartilhados `SYN-CUSTOMER-*`; endereços fictícios em cinco cidades/UF, CEP fictício zerado; status 60/25/10/5 por cento, aproximadamente 5% excluídos; datas distribuídas por 365 dias; 1–8 itens com pesos 40/25/15/8/5/3/2/2 e preços em centavos exatos. Nomes/ruas/itens recebem rótulo SYN; nenhum CPF real. Lote incrementa versão do cache na mesma instrução/transação.
- Segurança/consistência: IDs retornados pelo INSERT mapeiam snapshots/itens, sem assumir sequência de identity. Inserções usam CTEs de escrita e constraints existentes; repetição colide no número e falha atomicamente, sem sobrescrever outros dados. A instrução final informa somente rótulo e contagens técnicas.
- Evidências: revisão estática da instrução e `git diff --check`; execução real de 100.000 pedidos, relações/UUIDs e medições de volume ficam sob responsabilidade do coordenador. Nenhum resultado de performance é presumido.
