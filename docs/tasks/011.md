# 011 — Reservas de arquivos com caminhos canônicos

- Escopo: impedir que aliases textuais de caminhos burlem reservas entre tarefas paralelas.
- Responsável: agente replication, coordenador revisa integração.
- Branch: `feature/011-reservas-worktrees`; worktree exclusivo `/private/tmp/naporta-011`, criado de `origin/develop` atualizado.
- Dependência: implementação do fluxo da branch `feature/005-fluxo-sequencial-worktrees`, incorporada localmente por solicitação do coordenador.
- Arquivos próprios: `scripts/git/start-task.sh`, `scripts/git/task-flow.sh`, `scripts/ci/validate.py`, este registro.
- Contrato: FILES e planos de tarefas exigem caminhos relativos canônicos. `./`, segmentos `.`, barras duplicadas/finais e raiz `.` são recusados antes de qualquer reserva. Reservas antigas não canônicas interrompem nova ativação até liberação e novo registro. Nomes com prefixo semelhante sem relação de diretório continuam independentes.
- Validação em 2026-10-16: `make pipelineCheck` aprovou 97 verificações, incluindo os 13 novos cenários; `make docsCheck` aprovou 26 arquivos, zero erros. A suíte usa somente repositório remoto local, worktrees e registros descartáveis. Nenhuma branch/arquivo das outras tarefas foi editado.
- Limites: protocolo de coordenação no clone; não impede edição manual fora dos arquivos reservados. Links simbólicos e diferenças de caixa não integram o contrato de caminhos canônicos desta correção.
