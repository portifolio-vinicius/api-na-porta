## Comportamento

`SEED_PROFILE=basic` (padrão) preserva o arquivo básico original. `SEED_PROFILE=full` acrescenta cinco pedidos fictícios determinísticos: todos os quatro status, diferentes datas, número textual com zeros à esquerda, múltiplos itens e um pedido excluído logicamente. São seis pedidos e onze itens no conjunto completo. UUIDs/chaves são estáveis. Pedidos já existentes e seus snapshots/itens, inclusive alterações manuais, permanecem intactos. Colisão de número externo reprova a transação em vez de modificar dados externos.

Cada execução bem-sucedida, inclusive uma repetição sem novos registros, incrementa `cache_versions.orders` na mesma transação. Perfil desconhecido é rejeitado antes de qualquer alteração. O usuário de demonstração continua sob controle do comando backend existente, com senha privada; nenhum usuário ou hash adicional é inserido neste SQL.

## Evidências

`python3 backend/test/integration/demoSeed.py`: aprovado inicialmente com 14 verificações reais em PostgreSQL 18 Docker usando imagem fixada, tmpfs, segredo por variável e migrations pelo executor existente. Foram confirmados status, datas, UUID/chaves estáveis, soft delete, decimais exatos, múltiplos itens, preservação integral após edição/repetição, dados externos intactos e invalidação de cache inclusive no perfil básico. O teste também cobre perfil inválido sem efeitos. Foi acrescentada verificação explícita do perfil padrão para a execução final.

Nenhuma migration ou fixture básica foi alterada. Makefile e bootstrap local permanecem sob responsabilidade de 009; o coordenador integra o perfil completo e o teste à esteira final.
